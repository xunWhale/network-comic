# 小鲸鱼的数通小剧场：路由器与下一跳的秘密

这是写给**刚学完静态路由、但还没搞明白为什么这么配**的数通入门漫画系列。

- [第一弹：路由器与下一跳](index.html)
- [第二弹：ARP 寻址与广播风暴](arp.html)
- [在线演示：ARP 寻址与广播风暴](https://xunwhale.github.io/network-comic/arp.html)

## 第一弹：路由器与下一跳

不讲命令，先讲画面：把一次跨网段通信想成赛博快递站里的一件包裹——终点地址不变，沿途每一站换车牌，路由器只负责把它交给下一位小哥。

## 第二弹：ARP 寻址与广播风暴

回答初学者最容易卡住的问题：我知道下一跳的 IP，怎么拿到它的物理 MAC？

| 幕 | 讲什么 | 一句话 |
| --- | --- | --- |
| 一 | ARP Request 广播 | 目标 MAC 全 F，大喇叭问“谁是 192.168.1.2” |
| 二 | ARP Reply 单播 | 真正的机主回答“我是，车牌 CC:CC” |
| 三 | ARP 缓存与老化 | 学到的 IP ↔ MAC 先记下来，动态条目几分钟后刷新 |
| 四 | 二层环路与广播风暴 | 没开 STP 时，广播在交换机之间无限复制 |

打开 `arp.html`，点击首屏「大喇叭广播喊话」，可以看到广播包从 PC1 出发，经交换机泛洪到 PC2、PC3、PC4；非目标节点打叉，PC2 单播回复并点亮 ARP 缓存表。

## 第一弹内容

| 幕 | 讲什么 | 一句话 |
| --- | --- | --- |
| 一 | IP 与 MAC 的分工 | IP 找终点，MAC 找这一站 |
| 二 | 路由表与下一跳 | 路由表不是地图，是分拣员的派件清单 |
| 三 | 子网掩码与最长匹配 | 把地址切成「区域 + 门牌号」 |
| 四 | 静态路由命令 | 命令就是给路由器立一块路标 |

首屏点「发包裹」，可以看到数据包从 PC1 经 R1、R2 到 PC2：**目的 IP 全程不变，MAC 每跳重新封装**。

## 自审

`check_overlap.py` 用 Range 取每段文字自己的行盒，两两比对矩形，在 `index.html` 和 `arp.html` 的 1440 / 900 / 390 三档宽度各跑一遍。

```bash
python3 check_overlap.py   # 两页均为 0 / 0 / 0
```

机检 0 FAIL 不代表没毛病，仍应结合 `preview-arp.png` 逐段检查首屏、四幕卡片和页脚是否无遮挡。
