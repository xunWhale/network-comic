路由器与下一跳的秘密

把一次跨网段通信，想成赛博快递站里的一件包裹。终点地址不变，沿途每一站换车牌；路由器只负责把它交给下一位小哥。

包裹还在 PC1，等你发车
赛博快递站 · 实时线路 准备中
目的 IP：10.2.0.20　·　这张单子一路不变
等待发车：PC1 准备把包裹交给第一跳 R1
每过一跳，MAC 车牌会重新封装一次
IP 地址终点收件地址
MAC 地址这一站的车牌
下一跳下一个接棒的人
幕一
地址先分工

IP 找终点，MAC 找这一站。

小鲸鱼只看懂“送到哪一个网段”，快递车只认“眼前这位邻居的车牌”。两种地址都重要，但负责的事情不同。

IP 像快递单上的最终地址：跨过几站，目的地仍是同一个。

目的 IP：一张不变的快递单

路由器拆开包裹看的是目的 IP。它用这个地址决定：应该往哪一个网段继续送。

MAC 像这一站的车牌：PC1→R1、R1→R2，每一段都会重新封装。

源 MAC / 目的 MAC：只管眼前一跳

到了 R1，上一段的 MAC 头会被拆掉，换成“R1 发给 R2”的新车牌。IP 还在原来的快递单上。

记忆口诀： IP 是“我要去哪儿”，MAC 是“这一段交给谁”。
幕二
小狗来查表

路由表不是地图，是分拣员的派件清单。

小狗分拣员不需要知道全世界怎么走。它只要查到：这个目的网段，从哪个门出去，交给哪位下一跳小哥。

看目的网段，选出口和下一跳。路由表就是这张“怎么派件”的清单。

查表三问

目的网段出接口下一跳
10.2.0.0/24GE0/0/1192.168.1.2
0.0.0.0/0GE0/0/0192.168.1.1
翻译：去 10.2.0.0/24 的包，从 GE0/0/1 出门，交给 192.168.1.2。
R1 不会把包裹“凭空传送”到 PC2，只会交给相邻的下一跳。

下一跳到底是什么？

它通常是和当前路由器直接相连的另一台路由器接口地址。像接力赛：你只需要知道下一个接棒的人，再由他继续往下查表转发。

注意：下一跳填的是对方的 IP 地址（例如 192.168.1.2），不是 MAC 地址，也不是终点 PC2 的 IP。
幕三
邮编要分级

子网掩码：把地址切成“区域＋门牌号”。

同一个 IP，掩码不同，分组结果就不同。先看网络号，再看主机号；路由器才能知道“是不是这一片”。

/24 · 精确到小区
255.255.255.0

前 24 位是网络号，后 8 位是主机号。
10.2.0.0 这一片里能放 254 台主机（去掉全 0 和全 1 两个）。

/16 · 先看大区
255.255.0.0

前 16 位是网络号，后 16 位是主机号。
10.2.0.0 这次覆盖的范围更大，包含 65534 台主机。

最长匹配

同一条路，优先看“更具体”的那张路标。

如果路由表同时有 /16 和 /24，目的地落在 /24 里，就优先走 /24。像“先到城市，再精准到小区”，具体的地址更有指向性。

路由范围谁优先
10.2.0.0/16大区备选
10.2.0.0/24小区更具体，优先

命令翻译器

静态路由命令，就是给路由器立一块路标。

华为常见写法把四件事按顺序说清楚：去哪里、用什么掩码、交给谁。命令背后，仍然是那张派件清单。

读成中文就是：去 10.2.0.0/24 这个网段的包，按 255.255.255.0 判断是不是这一片，交给邻居 192.168.1.2 接着送。
避坑提醒
!
别把下一跳写成自己。

R1 的下一跳应该是邻居 R2 的地址。写成 R1 自己，包裹会在原地绕圈，像把快递交回自己手里。

最后把整件事串起来

PC1 先看目的 IP → R1 查路由表 → 按最长匹配找到目的网段 → 从指定接口把包交给下一跳 → 每一跳换 MAC，直到 PC2 收到。IP 管全程，MAC 管一段。

记住：IP 管全程，MAC 管一段。
