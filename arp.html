ARP 怎么把 IP 找成 MAC 车牌？

路由器查表知道下一跳 IP 是 192.168.1.2，但网线和交换机只认 MAC 车牌。不知道对方车牌，就在局域网拿大喇叭喊一声。

幕一
大喇叭找人

ARP Request：谁是 192.168.1.2？

PC1 知道下一跳的 IP，却没有它的 MAC。于是把目的 MAC 写成全 F，交给交换机做广播：除了来时的端口，其他端口都复制一份转发。

交换机像传声筒：收到目的 MAC 为全 F 的广播帧，向除入口外的所有端口复制一份。

全 F 不是某一台机器

FF:FF:FF:FF:FF:FF 表示“所有人”。广播包不会直接命中 PC2，而是先让同网段的每台设备都听见这一嗓子。

为什么全网都能听见

交换机只看二层，不拆 IP

交换机工作在二层（数据链路层），它眼里没有 192.168.1.2 这种 IP 地址，只有端口和 MAC 地址。

泛洪规则：看到目的 MAC 是 FF:FF:FF:FF:FF:FF，直接从其他所有活跃端口复制转发。
广播范围：同一片局域网（同一个 VLAN / 广播域），广播包不会自己穿过路由器。
幕二
对号入座

ARP Reply：我是！我的车牌是 CC:CC。

PC3、PC4 拆开看发现目标 IP 不是自己，默默丢掉。只有 PC2 对上号，沿着交换机单播回复 PC1。

单播只给 PC1：目的 MAC 直接填成 AA:AA，交换机不再打扰 PC3 和 PC4。

单播回答，安静又精准

ARP Reply 是单播帧。因为 PC2 在刚才的广播包里已经记住了 PC1 的源 MAC，回信直接点名送达。

每台电脑收到广播后的反应

只有对上 IP 的人会回答

设备核对目标 IP动作
PC3192.168.1.3 ≠ .2默默丢弃
PC4192.168.1.4 ≠ .2默默丢弃
PC2192.168.1.2 == .2单播回复 CC:CC

同一刻交换机自己也顺便学了一手：它通过 PC1 发广播的入端口，记住了“PC1 的 MAC 在 1 号口”，所以回复能一步到位。

记忆口诀：提问用广播（大家都听见），回答用单播（只给指定车牌）。
幕三
记事本备忘

学到的 MAC，先记下来。

PC1 收到回复后，把“192.168.1.2 对应 CC:CC”放进 ARP 缓存表。动态条目通常过几分钟会老化，过期再重新问一次。

缓存是局部的速记本，不是永久档案；老化后会刷新，避免记住已经换人的旧车牌。

缓存让局域网少一点噪声

每一次发数据包前，设备都会先查 ARP 缓存。命中就直接套上对方的 MAC 车牌；没命中或过期了，才发一次广播问人。

一张表就够

IP ↔ MAC 的临时通讯录

ARP cache (arp -a)状态 / 老化时间
192.168.1.2 → CC:CC动态 · 238s
192.168.1.3 → DD:DD动态 · 115s
192.168.1.1 → AA:AA本机接口

缓存记录的是“这一段局域网里，我最近联系过谁”。它就像手机里的临时通话记录，会随着网络变化自动淘汰刷新。

为什么要设置老化时间？
设备可能换新网卡、虚拟机可能漂移到别的宿主机，旧车牌不能永久信任。
幕四
致命回音壁

二层环路没开 STP，广播会无限复制。

两台交换机被错误地用两条网线首尾相连，广播包就像站在两面镜子中间无限反射。每绕一圈副本翻倍，最终把整张网打瘫痪。

没有 STP 的二层环路：二层广播帧没有 TTL 寿命限制，没人告诉它“到此为止”。

广播包不会自己停

三层 IP 包头里有一个 TTL 计数器，每过一台路由器减 1，归零就丢弃；二层以太网帧没有 TTL 这个刹车，一旦成环就永不停止。

避坑提醒

发现网卡灯狂闪、全网断线，先查二层环路

!
STP（生成树协议）是交换网的安全护栏。

它会在物理环形链路里自动在逻辑上“堵死”一条备用接口，消除环路；只有主网线断了，才会秒级放开备用线。

✓
别把“正常 ARP 广播”当成故障：

正常局域网里每天都在发 ARP 广播。真正致命的是“广播帧 + 物理二层环路 + 交换机没开 STP”。

串回第一弹：路由器在三层帮我们隔离广播域；而在同一个网段内，靠 ARP + STP 协同工作。
记住：先用 ARP 广播问出车牌，再用单播精准送货。

广播是找人，缓存是记事，STP 是给二层环路装护栏。
